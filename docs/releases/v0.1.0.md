# cobot v0.1.0

First tagged release of cobot — a pure-Go, zero-third-party-dependency agent SDK extracted from gline (Cline lineage), designed to be embedded in-process by hosts such as Maestro.

> **Scope note**: the `v0.1.0` tag points at commit `4eb4858`, the **M0–M3 completion point**. Work merged to `main` afterwards — the M4 compaction strategies (`compact` package, LLM summarization), the structured `RunResult` API, examples and bilingual docs — is **not** part of this tag and will ship with a later tag (v0.1.1 / v0.2.0). Keep this in mind when pinning with `go get github.com/liup215/cobot@v0.1.0`.

## Highlights

- **Zero dependencies**: Go 1.25, `go.mod` requires stdlib only (runtime and tests).
- **Root-package facade**: a single `cobot.NewAgent(cobot.Config{...})` entry point; every config field optional with documented defaults; type aliases (`Callback`, `ToolGuard`, `Store`, `Provider`, ...) so hosts implement hooks importing only the root package. `Agent.Run(ctx, task)` runs the loop to the `attempt_completion` terminal protocol.
- **Providers**: OpenAI-compatible adapter (SSE streaming, incremental `tool_calls`, `reasoning_content`) and a native **Anthropic Messages** adapter (full SSE event set, thinking → reasoning channel, ephemeral `cache_control` on the last system block, `stop_reason` mapping, `HTTPError` with `Retry-After`); plus `mock` and `scripted` providers for deterministic offline testing.
- **Tool system**: `tools.Registry` with the built-in tool set (read_file / write_to_file / replace_in_file / execute_command / search_files / list_files / attempt_completion / ask_followup_question / plan_mode_respond), XML fallback parsing, and a prompt-to-registry guard test keeping the system prompt and the registered tools in sync.
- **ToolGuard (PreToolUse approval gate)**: consulted before every tool execution on both execution paths; deny feeds the reason back to the model, an `ErrAbortRun` error aborts the run, unexpected errors fail closed.
- **Agent loop** (inherited from gline, hardened): `attempt_completion` termination protocol, Plan/Act modes, correction loop, stream pre-dispatch of read-only tools (race-tested), streaming callbacks, exponential-backoff connection retries (1s/2s/4s/8s, server `Retry-After` wins, mid-stream errors never retried), optional `Store` persistence, context cancellation and cooperative `Abort()`.
- **Context management**: automatic hard trimming past the token budget (gline watermark semantics), including the 100% pre-send hard trim.

## Known limitations

- **No LLM-summarization compaction in this tag**: the `compact` package (Trim/Summarize/Combo strategies, 60%/80% strategy hooks, structured five-section summaries) was finished after this tag on `main`. v0.1.0 has only the gline-lineage hard trim.
- `Run` returns only `error` in this tag; the structured `RunResult` (FinalText, per-run token usage, turns, duration) landed on `main` afterwards.
- File/command tools perform **no working-directory sandboxing** (baseline semantics); use `ToolGuard` for execution control.
- Anthropic thinking signatures are not persisted (thinking content is not replayed back to the API).
- Pre-dispatch may execute a read-only tool twice when the stream finishes instantly (best-effort overlap semantics inherited from gline).
- No TUI, extensions, session trees, OAuth, MCP, memory, browser or orchestration — explicitly out of scope for v0.1.
- Single-maintainer test strength; behavior is pinned by an ever-growing suite of `-race` behavior tests.
